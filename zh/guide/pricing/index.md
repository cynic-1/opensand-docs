# 价格与用量

OpenSand 的实际扣费取决于模型、输入输出 Token、图片/视频参数以及站点当前配置。文档不写死价格，避免用户看到过期信息。

## 在哪里看价格

- 控制台的模型或价格页面会显示当前可用模型与费率。
- 请求日志会显示单次请求的用量和消耗。
- 余额或额度不足时，请先降低模型规格、减少输出长度，或补充额度。

## 文本模型如何计费

文本模型通常按 Token 计费：

- 输入 Token：用户消息、系统提示词、历史上下文。
- 输出 Token：模型生成的内容。
- 长上下文和多轮对话会增加输入 Token。

你可以把 Token 理解成模型看到和生成的文本片段。中文、英文、符号都会被拆成 Token。一次对话越长，历史消息越多，输入 Token 就越高。

### 为什么同一个问题费用可能不同

- 选择的模型不同：高级模型通常更贵。
- 输出长度不同：让模型写长文会增加输出 Token。
- 上下文不同：带上很多历史消息会增加输入 Token。
- 是否开启工具调用、推理、图片或视频能力。

### 新手建议

刚开始接入时，先用中低成本模型跑通流程。等提示词和业务流程稳定后，再切换到更强模型。

## 图片和视频如何计费

图片和视频模型通常还会受到尺寸、时长、分辨率、是否生成音频等参数影响。提交高成本任务前，建议先用小尺寸或短时长测试。

视频生成尤其要注意：时长越长、分辨率越高、是否生成音频，都会影响成本和等待时间。

## 控制成本的建议

- 先用较便宜或较快的模型做草稿。
- 设置合理的 `max_tokens` 或输出长度。
- 视频任务先用短时长验证提示词。
- 定期查看用量日志，排查异常消耗。

## 如何排查费用异常

1. 打开请求日志，按时间找到异常请求。
2. 查看使用的模型，确认是否误用了高成本模型。
3. 查看输入和输出 Token，确认是否传入了过长上下文。
4. 检查是否有脚本或客户端在循环重试。
5. 给不同项目使用不同 API Key，方便定位来源。
